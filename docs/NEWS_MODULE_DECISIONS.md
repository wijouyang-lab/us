### 方案 B：免费 API（低成本，有配额限制）⭐ 推荐

- **更新频率**：**独立低频 job 每 30–60min**（不跟 15min dashboard-data，省配额）；Finnhub 60/min 充裕。

## 4. Q6 联动分析（news_cn 能否直接接入新板块）

**事实基础（来自 `NEWS_CN_GAP_INVESTIGATION.md` + 代码核查）：**
- `news_cn` = AI 生成的**中文新闻核查**，落 `ai_snapshot.csv`，经 `app.js:1306` 渲染到 `#aiNews`（**仅 Core 股票**）。
- 当前覆盖 **5/42**：5 只 Core_Dragon 有（FANG/GEV/HWM/SNPS/WRB）；37 空白 = 26 Observation 被 `scan.py:3109` 禁止生成 + 11 从未进 AI 管线 + 1 APA 反污染抑制。
- 根因 = **设计使然**（扩大覆盖 = 子任务 A 的设计变更，非修 bug）。

**能否直接接入新板块？——能，但只能覆盖 5/42，不能单独撑起联动块。**

| 维度 | news_cn 直接复用 | 需新增源补充 |
|---|---|---|
| 数据性质 | 中文、ticker 级、AI 核查（高质量） | 英文、市场级/任意 ticker |
| 现有覆盖 | 5/42（仅 Core） | 0 → 用 Finnhub 补到 42/42 |
| 渲染位置 | 每 ticker 卡片内 `#aiNews`（已有） | 新独立区块 |
| 适合角色 | 「持仓/推荐联动」子块的中文高亮 | 「市场新闻流」主块 |

**推荐结构：两块分离 + 可选高亮（= Q6 选项③ 混合）**
1. **「市场新闻流」块**（独立、市场级）：Finnhub `/news` 按 Q5 关键词过滤 → 解决"广度"。
2. **「持仓/推荐联动」块**（ticker 级）：Finnhub `/company-news`（英文，补 37 缺口）+ `news_cn`（中文，现有 5 只高亮）→ 解决"与持仓/候选相关"。
3. **可选**：对已在 portfolio/observation 的 ticker 加视觉高亮（如边框/角标），不引入新数据源。

> 即：**news_cn 可直接进新板块的"联动子块"，但必须与市场流分为两块**；单靠 news_cn 无法填满联动块（仅 5/42），缺口由 Finnhub `/company-news` 补齐。子任务 A（扩 news_cn 覆盖到 Observation）与本板块**正交**——前者改 AI 生成 scope，后者是新展示层，可独立推进。

## 5. 推荐方案（我的明确判断）

**推荐：方案 B（Finnhub 免费为主 + news_cn 复用 + RSS 兜底），Q6=混合双块。**

理由（逐条对应你之前的约束）：
1. **零成本且合规**：Finnhub 免费 60/min = 个人/非商用许可，本看板符合；避开 NewsAPI 免费档的 TOS 与生产禁令。
2. **精准补掉已发现的缺口**：`news_cn` 仅 5/42 的根因是"设计使然"，短期无法靠展示层解决；Finnhub `/company-news` 对任意 ticker 拉取，**直接把联动块覆盖从 5/42 拉到 42/42**，不碰 scan.py AI 契约（不动子任务 A）。
3. **市场广度补齐**：`/news` 给 scan.py RSS 没有的"全市场流"，RSS 仅 10 mega-cap。
4. **尊重"展示聚合、非信号"铁律**：Finnhub 免费无实时 WebSocket、无复杂情感，天然止步于"看"，不越界到 Phase 5/7 交易信号。
5. **低工程风险**：独立低频 job（30-60min）不污染 15min 主刷新链路；缓存 JSON 中间层 + 沿用 `dashboard_export.py` 的 try/except 降级风格，新闻失败绝不阻断看板。
6. **不碰已推送代码 / 监控**：仅新增 fetch 模块 + 新区块，判决后实施。

**不推荐方案 C**：月费 $30–$450 对个人研究看板过度配置，且逼近"新闻→信号"范畴（属 Phase 5/7，本范围明确排除）。
**方案 A 仅作最小可行兜底**：若你希望判决后先用零成本验证 UI，可 A 先行、B 后续叠加。
