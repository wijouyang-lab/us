# 80% 股票天花板评估（只读 / 不实施）

> 目的：诊断"当前 4 只持仓已占 ~80% 股票上限，导致新买入被拦截、'浮动 3-5 只'的 5 只永远实现不了"的问题，并给出三个选项的权衡。
> 本文档**只做分析与推荐**，不含任何代码改动。所有行号、数值来自当前 `portfolio_50000.py` 与仓库内 `portfolio_50000_positions.csv`。

## 1. 现状

### 1.1 当前 4 只持仓占比（实测）

读取仓库内 `portfolio_50000_positions.csv`（OPEN 持仓，`Weight_Pct` 列）：

| Ticker | Unit_ID | Weight_Pct | Market_Value |
|---|---|---|---|
| ADSK | U001 | 19.74% | 10,120.05 |
| ANET | U002 | 19.87% | 10,186.78 |
| ISRG | U003 | 19.84% | 10,175.04 |
| KR   | U004 | 20.20% | 10,355.52 |
| **合计** | — | **79.65%**（≈ 用户所述 79.64%） | 42,837.39 |

> 计算口径：`Weight_Pct = Market_Value / (现金 + 股票总市值)`，由 `_stock_pct()` 同口径推导（`portfolio_50000.py:176`）。
> 4 只单只都贴近 **20%**（因 `_within_alloc` 单只上限 25%、且每只为 1 个 ~$10,000 的 Unit，占 $50,000 组合约 20%）。

### 1.2 `_within_alloc` 的 80% 上限怎么算的（贴代码）

`portfolio_50000.py:208-219`：

```python
def _within_alloc(rec, positions, transactions, equity):
    """#4 四维占比预审（股票侧）：单只≤25% / 总股票≤80%。
    返回 (ok, 原因)。期权≤15% 与现金≥5% 由期权引擎 / 预算双保险兜底，本函数只挡股票侧超配。"""
    stock_pct = _stock_pct(positions, transactions)          # 当前总股票占比
    new_size = unit_dollars_for(rec, equity)                 # 本次拟买入金额（~$10,000）
    proj_stock = stock_pct * equity + new_size               # 买入后总股票市值
    if new_size > equity * Decimal("0.25"):                  # 闸门 A：单只≤25%
        return False, "单只将超 25%"
    if proj_stock > equity * Decimal("0.80"):                # 闸门 B：总股票≤80%
        return False, "总股票将超 80%"
    return True, ""
```

- **闸门 A（单只≤25%）**：`new_size > equity * 0.25` → 1 Unit（$10,000）仅占 $50,000 的 20%，**不会触发**。
- **闸门 B（总股票≤80%）**：`proj_stock > equity * 0.80` → 当前已 79.65%，再加 1 Unit（$10,000 ≈ 20%）→ 投影 ~99%，**必然触发**，理由 `"总股票将超 80%"`。

`_stock_pct`（`portfolio_50000.py:176`）：

```python
def _stock_pct(positions, transactions):
    """当前总股票市值 / 总资产（现金 + 股票）。期权由期权引擎另计，不在此口径。"""
    cash = derive_cash(transactions)
    stock = ZERO
    for p in positions:
        if str(p.get("Status", "")).upper() == "OPEN":
            stock += dec(p.get("Market_Value")) or ZERO
    total = cash + stock
    return (stock / total) if total > 0 else ZERO
```

## 2. 问题

1. **4 只 × ~20% ≈ 80% 天花板**：当前组合已贴满"总股票≤80%"上限。
2. **任何新买入会被拦**：第 5 只（无论评分多高）在 `process_buys`（`portfolio_50000.py:517` 调用 `next_free_unit`）走到 `_within_alloc` 时，闸门 B 必败，理由 `"总股票将超 80%"`，`log` 记 `⏸ ... 占比约束拦截 → 跳过`。
3. **"浮动 3-5 只"的 5 只永远实现不了**：#4 设计目标是"浮动 3-5 只"，但 80% 天花板在第 4 只之后就封顶，**第 5 只物理上无法开仓**（除非现有某只被卖出释放额度）。
4. **UNIT_IDS 扩到 10 个（本次任务 2）只是解除"名额"瓶颈，不解除"占比"瓶颈**：即使有 U005-U010，第 5 只仍会被占比闸门 B 拦截——两个瓶颈必须分别解决。

> 结论：占比天花板（80%）是"5 只可达性"的真正 blocker；Unit 名额（4→10）是必要但不充分条件。

## 3. 三个选项（分析，不实施）

### 选项 A：降单只上限 25% → 20%

- 思路：把闸门 A 从 25% 降到 20%，使"单只 1 Unit ≈ 20%"成为硬对齐；但**这不改总股票上限 80%**。
- 对现有持仓的影响：**无**。现有 4 只每只 ~20%，恰好贴新单只上限，不会被触发卖出或重排。
- 对风控的影响：单只集中度下降（更分散），现金缓冲不变。
- 改动半径：仅 `portfolio_50000.py:215` 一处常量（`Decimal("0.25")` → `"0.20"`）。
- 能否解决 5 只问题：**不能**。总股票≤80% 不变，第 5 只仍被拦。此选项与"5 只可达"无关，价值在于"让单只上限与 1Unit 实际占比一致、语义更清晰"。

### 选项 B：升总股票上限 80% → 90%

- 思路：把闸门 B 从 80% 提到 90%，为第 5 只（再 +20%）腾出空间：79.65% + 20% = 99.65% > 90% 仍超？需注意——**投影是加 1 Unit 后判断**，若上限 90%，则 79.65% + 20% = 99.65% **仍超 90%**，第 5 只仍被拦！
  - 要让 5 只（5×20%=100%）可行，总股票上限必须 ≥ 100%，但这等于"取消股票上限"，与风控精神冲突。
  - 更合理配套：同时**降单只上限到 ~16-18%**（让每只为 $8k-9k），使 5 只 ≈ 80-90%。即 A+B 组合。
- 对现有持仓的影响：**无**（现有 4 只已建仓，不受新上限回退影响；占比只在新买入时预审）。
- 对风控的影响：股票侧上限放宽，**现金缓冲从 ≥20% 降到 ≥10%**，组合对单一市场下跌的缓冲变薄（但期权引擎/现金双保险仍在）。
- 改动半径：`portfolio_50000.py:217` 一处常量（`"0.80"` → `"0.90"`），并建议配合 A 调整单只上限以保证 5 只可行。

### 选项 C：保持现状（"浮动 3-5"实际是"浮动 3-4"）

- 思路：承认 80% 天花板下组合最多稳定持有 4 只股票，"浮动 3-5 只"的文档/口径修正为"浮动 3-4 只"。
- 对现有持仓的影响：**无**。
- 对风控的影响：**最稳健**——保留 20% 现金缓冲，不放大市场暴露。
- 改动半径：仅文档/口径（`monday_check.sh`、相关计划文档中"浮动 3-5"措辞），**零代码改动**。
- 代价：放弃"5 只"目标；若业务上确实想要 5 只分散，此选项不满足。

## 5. 推荐（分析性，等用户拍板）

**若业务目标是"真正能到 5 只"**：选 **B + A 组合**——
- 总股票上限 80% → 90%（`portfolio_50000.py:217`）；
- 单只上限 25% → 18%（`portfolio_50000.py:215`），使 5 只 × 18% ≈ 90% 恰好贴新上限；
- 现有 4 只不受影响（占比预审只作用于新买入），第 5 只可开仓；
- 现金缓冲从 20% 降到 10%，需在周一目了然文档里标注"组合更偏股票、现金缓冲变薄"。

**若风控优先级高于"5 只"目标**：选 **C（保持现状）**，并把口径统一为"浮动 3-4 只"，零风险、零改动。

**A 单独做**价值有限（不解决 5 只），但可作为 B 的配套使语义自洽，建议与 B 同批。

> 注意：本次任务（4 件）**未改动** `_within_alloc` 的任何常量——80% / 25% 上限保持原样，仅把 UNIT_IDS 名额从 4 扩到 10。占比瓶颈的处置**留待用户就 A/B/C 拍板后再实施**，避免未授权改动主链路风控逻辑。
